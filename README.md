# 外構かんたんプラン

外構工事の **現地調査 → 平面図 → 3Dパース → 見積もり** を、スマホ・タブレット・PC のブラウザだけで進められるアプリです。
現地調査と見積もりは、経験のない人でも「質問に答える・測る・選ぶ」だけで終わるように作っています。

## できること

| 画面 | 内容 |
| --- | --- |
| 1. 現調 | 8 ステップ。**既存図**は、近いパターンを選ぶと建物が入った図ができるので、ドラッグか数字で大きさを合わせるだけ。境界のブロック・フェンスは辺ごとにタップで置け、木・桝・メーターなども置けます。あとは質問に答え、チェックリストに沿って写真を撮ります。回答から「気をつけるポイント」（高低差・乗り入れ口・境界杭など）を自動で表示。現調シート（既存図つき）を印刷できます。 |
| 2. 平面図 | 既存図の上に、ご要望から部材を自動で配置。部材をタップで選び、ドラッグで移動、角の丸で大きさを変更（敷地や他の部材の端に吸着）。部材を置くたびに概算金額が変わります。 |
| 3. 3D | 平面図がそのまま立体に。視点（ななめ・正面・目線・真上）と時間帯（昼・夕方・夜）を切り替え、画像として保存、見積書への添付ができます。 |
| 4. 見積 | 平面図の面積・長さ・個数 × 単価で自動計算。数量・単価の手直し、行の除外、手入力の行、諸経費・値引き・消費税に対応。見積書（＋平面図＋完成イメージ）を印刷・PDF 保存できます。 |

そのほか

- **単価表**（設定）：材料と工事費を合わせた単価を自社の金額に書き換えられます。
- **会社情報**（設定）：見積書に印刷される会社名・住所・インボイス登録番号など。
- **バックアップ**（設定）：全データ（写真を含む）を 1 つのファイルに書き出し・読み込み。
- はじめて開くとサンプル案件が 1 件入っています。

## 使い方の流れ

1. 「新しい案件」で、敷地と建物のパターン（標準・間口が広い・間口がせまい など 6 種類）を選ぶ。
2. 現調の「既存図」で大きさを合わせ、境界にあるもの・撤去するものを入れる。続けて質問に答える。
3. 「まとめ」で **平面図を自動作成**（既存図はそのままで、ご要望の部材が置かれます）。
4. 平面図で位置や大きさを直し、必要な部材を「部材を追加」から置く。
5. 3D で確認し、気に入った視点で「見積書に添付」。
6. 見積で数量・単価を確認し、「見積書をつくる」→「印刷・PDF保存」。

既存のもの（ブロック塀・フェンス・木・物置・コンクリート）は、「そのまま残す」なら費用なし、
「撤去する」にすると撤去費が見積もりに入り、3D には出なくなります。

## 単価についての注意

初期値の単価はあくまで **参考値**（材工共・税抜）です。地域・仕入れ・現場条件で変わるため、
実際に使う前に、設定の「単価表」で自社の単価に変更してください。

## データの保存先

サーバーは使いません。データは **その端末のブラウザの中**（案件は localStorage、写真は IndexedDB）に保存されます。

- ブラウザのデータを消すと案件も消えます。定期的に設定の「バックアップ」で書き出してください。
- 別の端末に移すときも、バックアップの書き出し → 読み込みで移せます。

## 開発

```bash
npm install
npm run dev        # 開発サーバー
npm test           # 単体テスト（見積計算・自動レイアウト・編集の計算）
npm run build      # 型チェック＋本番ビルド（dist/ に出力）
npm run preview    # ビルド結果の確認
```

React + TypeScript + Vite、3D は three.js です。

`VITE_DEMO=1 npm run build` でビルドすると、ホームに「お試し用のページです」という案内が出ます
（印刷やファイル保存ができない埋め込み環境で見せるとき用）。

### 公開のしかた

GitHub Pages で公開する設定が入っています（`.github/workflows/deploy.yml`）。
`main` に変更が入るたびに、テスト → ビルドを行い、結果を `gh-pages` ブランチに置きます。

初回だけ、GitHub のリポジトリ画面で次の設定をします。

1. Settings → General → Danger Zone → Change repository visibility で **Public** にする
   （無料プランの GitHub Pages は公開リポジトリのみ対応）。
2. Settings → Pages → Build and deployment → Source を **Deploy from a branch** にし、
   Branch で **gh-pages** と **/ (root)** を選んで Save。

1〜2 分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で開けるようになります。
スマホでは「ホーム画面に追加」するとアプリのように使えます。

`npm run build` でできる `dist/` フォルダは静的ファイルだけなので、Netlify・Vercel・社内サーバーなど、
ほかの場所に置いても動きます（`base: './'` のためサブフォルダ配下でも可）。

### フォルダ構成

```
src/
  lib/
    catalog.ts         部材カタログ（種類・参考単価・図面での見た目）
    estimate.ts        見積計算
    surveyDef.ts       現調の質問と、注意ポイントの判定
    existing.ts        既存図（敷地と建物のパターン・境界にあるもの）
    planFromSurvey.ts  既存図＋ご要望 → 平面図の自動レイアウト
    migrate.ts         以前の版で保存したデータの移行
    photos.ts          写真の保存（IndexedDB）と縮小
    sample.ts          サンプル案件
  screens/             ホーム・案件・現調・見積・設定の各画面
  plan/                平面図・既存図のエディタ（描画・操作・吸着の計算）
  view3d/              3D パース（平面図 → three.js のシーン）
  print/               見積書・現調シート（A4 印刷）
  store.ts             状態の保存、画面遷移、確認ダイアログ
tests/                 単体テスト
```

部材や単価を増やすときは `src/lib/catalog.ts`、現調の質問を変えるときは `src/lib/surveyDef.ts`、
敷地のパターンを増やすときは `src/lib/existing.ts` の `PATTERNS` を編集します。

## いまの制限

- 敷地は長方形、道路は 1 面（図の下側）として扱います。
- 3D は平らな地面で表示します（高低差は現調の注意ポイントで知らせるのみ）。
- 平面図の面の部材（コンクリートなど）は長方形で、斜めには置けません（塀・フェンスなどの線は斜めも可）。
- データは端末ごとです。複数人・複数端末での共有には、サーバー側の保存機能の追加が必要です。
